#### 时间库

头文件\<chrono\>

时间间隔，计时：

```cpp
#include <chrono>
#include <iostream>
#include <thread>
int main() {
    auto start = std::chrono::system_clock::now();

    // ... 执行一些代码 ...
    
    std::this_thread::sleep_for(std::chrono::milliseconds(1000));
    auto end = std::chrono::system_clock::now();
    // 计算时间差：两个时间点相减，得到一个 duration
    auto elapsed = end - start;

    // 打印耗时（自动转换为毫秒并计数）
    auto ms_count = std::chrono::duration_cast
                    <std::chrono::milliseconds>(elapsed).count();
    std::cout << "代码执行耗时: " << ms_count << " ms" << std::endl;
    return 0;
}
```

- 从 C++20 开始，可以直接打印 `duration` 对象，不需要手动调用 `count()` 了，标准库会自动帮你拼接单位和数值。

获取时间戳，并转化成年月日格式

```cpp
#include <chrono>
#include <iostream>
#include <iomanip>
#include <sstream>

int main() {
    // 1. 获取当前系统时间点
    auto now = std::chrono::system_clock::now();
    
    // 2. 转换为 time_t
    std::time_t now_c = std::chrono::system_clock::to_time_t(now);
    
    // 3. 转换为本地时间结构体 (一定要用 localtime，不要用 gmtime)
    std::tm* local_tm = std::localtime(&now_c);

    // 4. 格式化输出：年-月-日 时:分:秒
    std::stringstream ss;
    ss << std::put_time(local_tm, "%Y-%m-%d %H:%M:%S");
    
    std::cout << "当前日期时间: " << ss.str() << std::endl;
    
    // 如果你只想提取出来存个变量：
    std::string date_str = ss.str();
    return 0;
}
```

#### 内存泄漏的根本原因

堆上内存由分配器动态分配，当分配的指针出了作用域失效后，如果没有主动释放内存，那么在分配器的记录中这部分内存仍然为占用状态，且由于没有指针指向它，没有办法在手动释放这块内存。

#### inline关键字

inline只是建议，真正是否执行取决于编译器，并且在debug版本下不起作用
高版本编译器下inline内联函数语法几乎废弃，主要用于声明内联变量，头文件中的有内联变量，且头文件被多个文件包含时，可以解决重定义问题，编译器仅保留一份

- 与普通函数区别：
  
  - 内联函数在调用处直接展开，调用时开销更少(不需要额外开辟栈帧以及参数传递等过程)
  
  - 内联成功之后，不会产生符号表
  
  - 内联只是建议，可以通过查看符号表等方法查看是否内联成功

#### 重载

- C++函数产生符号时，同时包含函数名和参数列表(C语言则不会，所以不支持重载)

- 重载函数得在同一个作用域，否则调用时会优先匹配更近的作用域

- const和volatile修饰的变量无法形成重载，修饰的指针则可以

- 仅仅返回值不同，不是重载

#### const修饰

- const修饰不能在作为左值，初始化之后不能修改，const变量初始化编译期常量则会直接在编译阶段做类似宏的替换

- C语言中的不同：
  
  - const修饰变量可以不初始化(之后没有机会修改)

- const指针转换：
  
  - 仅在一级指针以下可行
  - ```cpp
    int a = 0;
    const int *p = &a;
    // const int*  <-   int*  ✅正确
    // int*  <-   const int*  ❎错误
    ```
  - 二级指针及以上，需要额外考虑
  - ```cpp
    int b = 10;
    int *a = &b;
    const int **p = &a; //❎错误   
    /*  原因 此时的*p是const int*
    相当于const int* (*p) = &a，此时*p 和 a是同一个内存  存的都是一个地址
    而*p是可以用const int*来赋值的:
    const int b = 10;
    *p = &b 
    由于*p和a是同一个地址   相当于 a = &b
    即  const int* -> int*  ❎错误
    */
    /* 解决：
    显而易见   int *a ->const int *a  
    
    还有  const int * const *p = &a;    
    此时*p无法赋值，也就不存在 const int* -> int*
    */
    cout << typeid(*p).name();
    ```
  - `int * const p = &a;`此时`&p`的类型是`int * const *`

常出现的错误：

- 常量不能作为左值

- 不能把常量的地址泄露给一个普通指针或普通引用

顶层 const：修饰变量自身，只作用这个变量本身，对外的类型签名会把它忽略,即

const右侧没有*则const不参与类型*

但是！*编译器做左值赋值检查的时候，顶层 const 依然生效：变量不能被赋值*。

#### 工厂模式

**对象的创建和使用分离**，让子类或具体工厂类决定创建哪种对象。

###### 工厂方法模式

```cpp
#include <iostream>
#include <memory>
using namespace std;

// 产品基类
class Car {
public:
    virtual void drive() = 0;
    virtual ~Car() = default;
};

class BMW : public Car {
public:
    void drive() override { cout << "Driving BMW" << endl; }
};

class Audi : public Car {
public:
    void drive() override { cout << "Driving Audi" << endl; }
};

// 工厂基类
class CarFactory {
public:
    virtual unique_ptr<Car> createCar() = 0;
    virtual ~CarFactory() = default;
};

// 具体工厂1：生产 BMW
class BMWFactory : public CarFactory {
public:
    unique_ptr<Car> createCar() override {
        return make_unique<BMW>();
    }
};

// 具体工厂2：生产 Audi
class AudiFactory : public CarFactory {
public:
    unique_ptr<Car> createCar() override {
        return make_unique<Audi>();
    }
};

// 使用
int main() {
    unique_ptr<CarFactory> factory1 = make_unique<BMWFactory>();
    auto car1 = factory1->createCar();
    car1->drive();  // Driving BMW

    unique_ptr<CarFactory> factory2 = make_unique<AudiFactory>();
    auto car2 = factory2->createCar();
    car2->drive();  // Driving Audi

    return 0;
}

#### 代理模式

代理模式在不改变原始类的情况下，通过引入一个**代理类**来控制对真实对象的访问。代理类和真实类实现相同的接口，客户端通过代理类间接访问真实类。

###### 保护代理

```cpp
#include <iostream>
#include <string>
using namespace std;

// ========== 接口 ==========
class File {
public:
    virtual void read() = 0;
    virtual void write() = 0;
    virtual ~File() = default;
};

// ========== 真实对象 ==========
class RealFile : public File {
private:
    string filename;

public:
    RealFile(const string& name) : filename(name) {}

    void read() override {
        cout << "读取文件: " << filename << endl;
    }

    void write() override {
        cout << "写入文件: " << filename << endl;
    }
};

// ========== 代理 ==========
class FileProxy : public File {
private:
    RealFile* realFile;
    string username;
    string filename;

public:
    FileProxy(const string& file, const string& user) 
        : filename(file), username(user), realFile(nullptr) {}

    void read() override {
        if (username == "admin" || username == "guest") {
            getRealFile()->read();
        } else {
            cout << "权限不足：无法读取" << endl;
        }
    }

    void write() override {
        if (username == "admin") {
            getRealFile()->write();
        } else {
            cout << "权限不足：无法写入" << endl;
        }
    }

private:
    RealFile* getRealFile() {
        if (!realFile) {
            realFile = new RealFile(filename);
        }
        return realFile;
    }
};

// 使用
int main() {
    FileProxy adminFile("data.txt", "admin");
    adminFile.read();   // 读取文件: data.txt
    adminFile.write();  // 写入文件: data.txt

    FileProxy guestFile("data.txt", "guest");
    guestFile.read();   // 读取文件: data.txt
    guestFile.write();  // 权限不足：无法写入

    FileProxy userFile("data.txt", "user");
    userFile.read();    // 权限不足：无法读取

    return 0;
}
```

#### 适配器模式

**适配器模式**是一种结构型设计模式，它**将一个类的接口转换成客户端期望的另一个接口**，使原本因接口不兼容而无法一起工作的类能够协同工作。

```cpp
#include <iostream>
#include <memory>
#include <string>
using namespace std;

// ========== 1. 被适配者（已有类，接口不兼容） ==========
class OldPrinter {
public:
    void printOld(string text) {
        cout << "[旧打印机] " << text << endl;
    }
};

// ========== 2. 目标接口（客户端期望的） ==========
class NewPrinter {
public:
    virtual void print(string text) = 0;
    virtual ~NewPrinter() = default;
};

// ========== 3. 对象适配器（使用组合） ==========
class PrinterAdapter : public NewPrinter {
private:
    OldPrinter* oldPrinter;  // 持有被适配者

public:
    PrinterAdapter(OldPrinter* printer) : oldPrinter(printer) {}

    void print(string text) override {
        // 适配：调用旧接口
        oldPrinter->printOld(text);
    }

    ~PrinterAdapter() {
        delete oldPrinter;
    }
};

// ========== 使用 ==========
int main() {
    // 客户端只知道新接口
    NewPrinter* printer = new PrinterAdapter(new OldPrinter());
    printer->print("Hello World");

    delete printer;
    return 0;
}
```

#### 观察者模式

```cpp
#include <iostream>
#include <vector>
#include <memory>
#include <string>
using namespace std;

// ========== 前向声明 ==========
class Observer;

// ========== 主题接口 ==========
class Subject {
public:
    virtual void attach(Observer* observer) = 0;
    virtual void detach(Observer* observer) = 0;
    virtual void notify() = 0;
    virtual ~Subject() = default;
};

// ========== 观察者接口 ==========
class Observer {
public:
    virtual void update(const string& message) = 0;
    virtual ~Observer() = default;
};

// ========== 具体主题 ==========
class NewsPublisher : public Subject {
private:
    vector<Observer*> observers;
    string latestNews;

public:
    void attach(Observer* observer) override {
        observers.push_back(observer);
        cout << "[主题] 添加观察者" << endl;
    }

    void detach(Observer* observer) override {
        auto it = find(observers.begin(), observers.end(), observer);
        if (it != observers.end()) {
            observers.erase(it);
            cout << "[主题] 移除观察者" << endl;
        }
    }

    void notify() override {
        cout << "[主题] 通知所有观察者..." << endl;
        for (Observer* observer : observers) {
            observer->update(latestNews);
        }
    }

    // 业务方法：发布新闻
    void publishNews(const string& news) {
        latestNews = news;
        cout << "[主题] 发布新闻: " << news << endl;
        notify();
    }
};

// ========== 具体观察者 ==========
class EmailSubscriber : public Observer {
private:
    string name;

public:
    EmailSubscriber(const string& n) : name(n) {}

    void update(const string& message) override {
        cout << "[邮件订阅者 " << name << "] 收到邮件: " << message << endl;
    }
};

class SMSSubscriber : public Observer {
private:
    string phone;

public:
    SMSSubscriber(const string& p) : phone(p) {}

    void update(const string& message) override {
        cout << "[短信订阅者 " << phone << "] 收到短信: " << message << endl;
    }
};

class AppSubscriber : public Observer {
private:
    string device;

public:
    AppSubscriber(const string& d) : device(d) {}

    void update(const string& message) override {
        cout << "[App订阅者 " << device << "] 收到推送: " << message << endl;
    }
};

// ========== 使用 ==========
int main() {
    // 创建主题
    NewsPublisher publisher;

    // 创建观察者
    EmailSubscriber email1("Alice");
    EmailSubscriber email2("Bob");
    SMSSubscriber sms("138-0000-0000");
    AppSubscriber app("iPhone");

    // 订阅
    publisher.attach(&email1);
    publisher.attach(&email2);
    publisher.attach(&sms);
    publisher.attach(&app);

    cout << "\n=== 发布第一条新闻 ===" << endl;
    publisher.publishNews("C++ 20 新特性发布！");

    // 取消订阅
    publisher.detach(&email2);

    cout << "\n=== 发布第二条新闻 ===" << endl;
    publisher.publishNews("观察者模式示例");

    return 0;
}
```

#### 左值与右值

左值引用无法接收右值对象

```cpp
int &a = 10; //❎
```

需要转成const

```cpp
const int &a = 10; //✅
```

右值引用则可以正确接收右值对象

```cpp
int &&a = 10; //✅
```

但是右值引用变量a本身是一个左值

---

引用折叠规则(模板推导时候会用到)：左值引用会覆盖右值引用

- & + && = &(有左值引用则结果为左值引用)

- && + && =&&(全是右值结果才为右值引用)

```cpp
template<typename T>
void func(T&& param) {
}

int x = 10;
func(x);        // x 是左值 => T 推导为 int& => T&& = int& && = int& (左值引用)
func(10);       // 10 是右值 => T 推导为 int => T&& = int&& (右值引用)
```

##### std::move 和 std::forward

需要\<utility\>

std::move的作用是移动语义，可以把左值对象转换成右值对象

std::forward的作用是语义转发，即不改变原来是左值对象还是右值对象

```cpp
#include <iostream>
#include <utility>
using namespace std;

class Test {
public:
  Test(const string &s) { cout << "拷贝构造: " << s << endl; }
  Test(string &&s) { cout << "移动构造: " << s << endl; }
};

template <typename T> Test *create(T &&arg) {
  // 引用折叠后 原先传入的语义保持不变，但是变量(即使是右值引用)arg本身是一个左值
  // 而使用forward语义转发则可以正确匹配对应的构造函数
  // 如果不使用forward转发理论上只会调用拷贝，但是此处有一个例外，下文p3创建使用的
  // “temp”类型是const char* 会隐式转换为string产生一个临时对象(右值),导致结果
  // 出现移动构造函数的调用
  return new Test(std::forward<T>(arg));
}

int main() {
  string s = "hello";
  Test *p1 = create(s);  // 拷贝
  Test *p2 = create(string("world"));  // 移动
  Test *p3 = create("temp");  // 移动

  delete p1;
  delete p2;
  delete p3;

  return 0;
}
```

public:
    shared_ptr<A> a;  // B 持有 A（循环引用！）
    ~B() { cout << "B 析构" << endl; }
};

int main() {
    auto a = make_shared<A>();
    auto b = make_shared<B>();
    a->b = b;
    b->a = a;
    // ❌ 循环引用，A 和 B 永远不会析构！
    // 引用计数永远为 1（相互持有）
    return 0;
}
```

解决办法，使用weak_ptr，weak_ptr不可进行访问资源等操作，需要使用时需先使用lock方法提权，得到对应资源的shared_ptr在进行操作

```cpp
#include <memory>
#include <iostream>
using namespace std;

int main() {
    shared_ptr<int> sp = make_shared<int>(42);
    weak_ptr<int> wp = sp;  // 不增加引用计数

    cout << "引用计数: " << sp.use_count() << endl;  // 1

    // ✅ 检查资源是否还存在
    if (auto temp = wp.lock()) {  // 获取 shared_ptr
        cout << "值: " << *temp << endl;
    } else {
        cout << "资源已释放" << endl;
    }

    sp.reset();  // 释放资源

    if (auto temp = wp.lock()) {
        cout << "值: " << *temp << endl;
    } else {
        cout << "资源已释放" << endl;  // ✅ 会执行
    }

    return 0;
}
```

##### 删除器

```cpp
#include <iostream>
#include <memory>
using namespace std;

// 删除器类型：函数指针或函数对象
template <class T> class Deletor {
public:
  void operator()(T *ptr) { 
    cout << "自定义删除器释放 int: " << *ptr << endl;
    delete[] ptr; }
};
void my_deleter(int *p) {
  cout << "自定义删除器释放 int: " << *p << endl;
  delete p;
}

int main() {
  // 方式1：自定义类作为删除器
  unique_ptr<int, Deletor<int>> p1(new int(42));
  // 方式2：自定义函数作为删除器
  unique_ptr<int, decltype(&my_deleter)> p1(new int(42), my_deleter);  
  // 方式3：Lambda 作为删除器
  auto lambda_deleter = [](int *p) {
    cout << "Lambda 删除器释放: " << *p << endl;
    delete p;
  };
  unique_ptr<int, decltype(lambda_deleter)> p2(new int(100), lambda_deleter);

  return 0;
}
```

##### make_shared

shared_ptr存在数据块和控制块(存放引用计数，包括weak和shared两种)，如果直接使用`shared_ptr<int> sp1(new int(10))`那么数据块和控制块内存独立。

而使用`auto sp1 = make_shared<int>(10);`那么数据块与控制块将存放在连续的内存中，以下是优缺点：

| 优点      | 缺点                  |
| ------- | ------------------- |
| 内存分配效率高 | make_shared无法自定义删除器 |
| 防止资源泄露  | 导致托管资源延迟释放          |




#### 内存模型和顺序
程序语句执行顺序可能并不会按照代码排列，编译器编译成汇编时可能会发生指令重排序

##### Sequential Consistency 
`std::memory_order_seq_cst` 标准库默认模型
一个多处理器系统是顺序一致的，当且仅当：**所有操作的结果，都等同于所有处理器上的操作按某种全局单一顺序执行，且每个处理器自己的操作在该顺序中保持其程序顺序。**
```cpp
// 初始 x = 0, y = 0

std::thread t1([]{
	x = 1;          // A
	int r1 = y;     // B
})

// 线程 2
std::thread t1([]{
	y = 1;          // C
	int r2 = x;     // D
})

```
不可能x和y同时为0也就是执行顺序不可能B<C且D<A并且同时A<B且C<D,
##### Relaxed
`std::memory_order_relaxed`
仅保证操作原子性，不对内存顺序做约束，使用较少，通常与其他变量不存在依赖关系
##### Acquire/Release
`std::memory_order_acquire` / `std::memory_order_release` / `std::memory_order_acq_rel`
通常读取时`load`用std::memory_order_acquire
写入时`store`用std::memory_order_release
acquire之后的语句不可以向前移动
release之前的语句不可以向后移动
读取加上修改再写入`fetch_add`使用std::memory_order_acq_rel
