## 面经C++

### 1. this指针作用

一个类可以实例化多个对象，如果其中一个函数需要传入另一个对象作为参数，那么就可以通过this指针来区分其中的成员属于谁，this指针本身是一个常量指针，指向无法改变，编译完后会成为每个成员函数的隐藏形参

### 2. new和delete

底层还是malloc和free,new[]分配内存的时候，如果对象比较复杂，存在析构函数等，会额外分配一块内存记录对象的个数，后续delete[]则会通过这个记录可以知道循环多少次执行每个对象的析构函数，对于简单类型int这些，即时使用new[]分配，使用delete释放是可行的，但是不推荐

### 3. static关键字

- 面向过程：修饰全局变量和函数的时候，全局变量和函数仅当前文件可见->符号表中作用域从全局变成局部。修饰局部变量->会将局部变量内存分配到.data段(初始化不为0)和.bss段(初始化为0)，局部变量原本不产生符号，通过ebp-偏移量访问，使用static修饰后也会产生符号，(每次运行函数有栈帧，栈帧的基地址ebp)

- 面向对象：static使得成员变量在对象间共享，使成员方法不再产生this指针，即不强制通过对象调用

### 4. 继承

类和类之间的关系，还有组合(包含)

优点：

- 1.代码复用；

- 2.通过基类纯虚函数定义接口规范，等待派生类实现，通过基类指针访问派生类对象并调用同名方法，实现多态，符合开闭原则，对修改关闭，对扩展开放

### 5. 多态、空间配置器、vector、list、map、multi_map

- 多态：静多态(编译器确定)，函数重载和模板，动多态(运行时)：虚函数，基类指针/引用指向派生类调用同名方法

- 空间配置器allocator：给容器使用，把内存分配和对象构造分开，把对象析构和内存释放分开，创建容器的时候仅分配内存而不需要创建对象，删除元素的时候只需要析构对象而内存还保留,对比new delete，无法仅申请内存

- vector:数组，适合随机访问，内存连续，priority_queue基于vector，支持随机(下标)访问

- list:链表，适合频繁增删，内存不连续

- map:映射表，[key,value]，底层是红黑树

- multimap：允许key重复，其他与map相同

- 红黑树性质：1.每个键都是红或者黑；2.根节点必须是黑色；3.红色节点不能父子相邻；4.从任意节点出发到任意叶子节点所经过的黑色节点数相同(保证最长路径不超过最短路径的两两倍)；5.叶子节点必须是黑色。

- 红黑树插入三种情况(最多旋转两次)，删除(最多旋转三次)四种情况

### 6. 如何防止内存泄露？智能指针？

内存泄漏：分配的堆内存没有释放(堆内存没有命名，只能通过指针来指向)

最常见的情况

```cpp
void fun()
{
    int *ptr = new int[1000];
    if(...)
    {
        //throw 抛出异常
        return;
    }
    delete []ptr;
}
```

智能指针原理：栈上对象出作用域会自动析构，可以在其析构函数中释放内存

智能指针：

- unique_ptr:不带引用计数，保证同一时间只有一个unique_ptr指向资源，禁用了拷贝构造和拷贝复制被删除，只有移动构造可以转移所有权。

- shared_ptr:带引用计数，指针本身的线程安全的，其引用计数的增减都是原子操作。

- weak_ptr:与shared_ptr区别，只观察对象的引用计数，无法直接访问对象，解决了交叉引用的问题

### 7. C++如何调用C语言接口

由于二者生成符号的方式不同，无法直接调用另一方的API接口,C语言的声明必须套在`extern"C"{}`里面

```cpp
#ifdef __cplusplus  //如果是C语言编译器，没有__cplusplus宏则下面语句不会展开
                    //如果是C++编译器，那么下面语句会展开
extern "C"{
#endif
int sum(int,int);
#ifdef __cplusplus
}
#endif
```

### 11. malloc和new

- 1.malloc只分配内存，不提供初始化，new底层仍然是malloc分配内存，但是还提供初始化

- 2.malloc分配失败返回`nullptr`,而new失败则抛出`bad_alloc`类型异常

- 3.malloc是C标准库函数，而new则是运算符`operator new`

- 4.malloc分配数组需要手动计算内存大小`malloc(sizeof(int)*10)`，而new则可以通过`new int[10]`直接分配数组，还可以通过`new int[10]{}`来初始化

### 15. STL迭代器失效的原因

迭代器一边读一边修改，通过迭代器增删一个元素之后，部分容器的中间位置增删会导致后面元素都移动，或者触发容器的扩容导致整个容器地址改变，这个时候原先的迭代器的指向的地址并未改变，所以会失效，可以通过对原先的迭代器进行重新赋值，一般删除和插入会返回前一个或者后一个元素的有效的迭代器

### 19. 构造函数和析构函数可以是虚函数吗，为什么

- 构造函数不可以，对象的虚函数指针在构造函数中初始化，而调用虚函数需要通过虚函数指针去虚函数表中找到对应的函数

- 析构函数可以，且当需要使用多态的时候，基类对象的析构函数必须是虚函数

### 20. 构造函数和析构函数可以抛出异常吗，为什么

- 构造函数可以：
  
  - 构造函数中抛出异常，会导致析构函数不能被调用，但对象本身已申请到的内存资源会被系统释放（已申请到资源的内部成员变量会被系统依次逆序调用其析构函数）
  
  - 因为析构函数不能被调用，所以可能会造成内存泄露或系统资源未被释放
  
  - 构造函数中可以抛出异常，但必须保证在构造函数抛出异常之前，把系统资源释放掉，防止内存泄露

- 析构函数不行：
  
  - 析构函数通常用于释放资源，抛出异常则后续代码不会执行，那么就会造成资源泄露的问题
  - C++标准默认情况下析构函数有noexcept关键字，默认不会抛出异常，如果抛出异常则会直接terminate()终止

### 25. const和static的区别

const定义的是常量，其编译方式是：编译过程中，把出现常量名字的地方用常量的值替换

```cpp
// int b = 10;
// const int a = b; //此时下面的a会被修改
const int a = 10;
int *p = (int *)&a;
*p = 20;
cout << a << "  " << *p << endl; // 10 20
return 0;
```

const可以修饰成员方法，被const修饰的成员方法，无法修改普通成员，只能修改mutable成员,类似的还有constexpr

| **关键字**         | **语义重点**                            | **计算时机**                                  |
| --------------- | ----------------------------------- | ----------------------------------------- |
| **`const`**     | **只读（Read-only）**，保证运行期不被修改         | 可以是编译期，也可以是运行期（如 `const int x = rand();`） |
| **`constexpr`** | **常量（Constant Expression）**，保证编译期已知 | **必须在编译期**计算出结果（常用于数组长度、模板参数等）            |

- 面向过程：

|      | const        | static     |
| ---- |:------------:|:----------:|
| 修饰变量 | 全局变量、局部变量、形参 | 全局变量，局部变量  |
| 修饰函数 | ❎            | ✅(仅当前文件可见) |

- 面向对象

|      | const           | statc           |
|:----:|:---------------:|:---------------:|
| 成员变量 | 仍依赖对象           | 不依赖于对象          |
| 成员方法 | 常方法，不能修改普通的成员变量 | 消除this指针，不依赖于对象 |

### 26.* 四种类型转换

- const_cast:增加或去除const属性，对于一个声明时是const的变量，去除const是UB,不建议

- static_cast:编译期类型检查，相对安全

- reinterpret_cast:强制转换，无安全保障，通常用于系统底层或硬件驱动

- dynamic_cast:支持RAII信息识别的类型转换，有继承关系的类之间使用，运行时检查

### 27. deque底层原理

动态开辟的二维数组，分为控制块和缓冲区，控制块保存每块缓冲区的地址，当头端或尾端缓冲区满时，只需要申请新的内存块，并把地址填入控制块即可，且头尾增删均为O(1)操作

### 28. 早绑定和晚绑定

| **特性**    | **静态绑定（早绑定 Early Binding）** | **动态绑定（晚绑定 Late Binding）**   |
| --------- | --------------------------- | ---------------------------- |
| **发生时机**  | **编译期**（Compile-time）       | **运行期**（Run-time）            |
| **绑定的依据** | 变量的**声明类型（静态类型）**           | 对象的**真实内存类型（动态类型）**          |
| **底层原理**  | 直接通过函数符号地址调用（硬编码）           | 通过对象的 `vptr` 查询虚函数表 `vtable` |
| **性能开销**  | 极高（零运行期开销，便于内联优化）           | 存在轻微开销（二次指针寻址）               |
| **典型代表**  | 普通全局/成员函数、函数重载、模板           | 虚函数（`virtual`）、多态指针/引用调用     |

注：用对象调用虚函数仍然是静态绑定，而通过指针或引用调用虚函数，需要在运行时通过虚函数指针访问虚函数表，是动态绑定

### 29. 指针和引用的区别

| **特性维度**        | **指针 (T*)**                  | **引用 (T&)**                                      |
|:---------------:|:----------------------------:|:------------------------------------------------:|
| **本质定义**        | **独立的变量**，存储的是另一个对象的**内存地址** | 另一个已有对象的**别名**，不占用独立地址空间（底层多由指针实现，但编译器对其包装）      |
| **空值状态**        | **允许为空**（`nullptr`）          | **绝对不能为空**，必须绑定到一个合法对象                           |
| **可变性（重新指向）**   | **可以重新指向**其他对象               | **初始化后不可重绑定**，终生绑定到初始对象                          |
| **初始化时机**       | 可以先声明，后赋值/初始化                | **必须在声明时初始化**（类成员变量须在初始化列表或类内赋初始值）               |
| **多级支持**        | 支持多级指针(如`int**`)             | 不支持多级引用（没有 `int&&` 这种“引用的引用”语法；右值引用 `&&` 是另一种概念） |
| **操作符语法**       | 访问成员用 `->`，解引用需用 `*`         | 访问成员直接用 `.`，使用时与普通变量完全相同                         |
| **`sizeof` 开销** | 永远返回指针本身的大小（64位系统下通常为8字节）    | 返回**所绑定对象**的大                                    |
